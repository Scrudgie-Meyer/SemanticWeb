# Лабораторна №2: LLM, векторний пошук і GraphRAG

Тема корпусу: **запчастини Nissan Qashqai 2011**. Є 10 власних зв’язних текстів,
8 запитань, Pydantic-схема та наскрізний `pipeline.py`.

## Поточний стан

Повний локальний запуск виконано через **Qwen3 4B Instruct + Qwen3 Embedding 0.6B**:
V2: 45 прийнятих LLM-фактів, 46 вузлів, 45 ребер, 12 спільнот, 12 чанків по 1024 виміри.
Фактичні результати та дві відповіді: `output/live/report.md`.
Розбір пошуку, порівняння RAG та відомі семантичні помилки: [REPORT.md](REPORT.md).
Оцінки всіх 20 фактів заповнено асистентом за оригінальними текстами:
**20/20 = 100% у новій вибірці** повністю коректних типізованих фактів.
Початкові 8/20 = 40% збережено в `output/baseline_v1/`.
Методика, зміни та обмеження точності — [REPORT.md](REPORT.md).

Запуск без API (`demo`) демонструє завантаження корпусу, авторські анотації,
TF-IDF-пошук, граф, Louvain, вибірку для аудиту й формування звіту.
**Demo не замінює обов’язковий LLM-експеримент.** Результати `live` зберігаються
окремо. Ручні оцінки та висновки про перевагу семантики не вигадуються.

## Встановлення та демонстрація (PowerShell з кореня репозиторію)

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r Lab2/requirements.txt
.\.venv\Scripts\python.exe Lab2/pipeline.py --self-check
.\.venv\Scripts\python.exe Lab2/pipeline.py --mode demo
```

Якщо `.venv` вже існує, перший крок пропустіть. Python 3.10+.
Для Gemini необов’язково встановлювати sentence-transformers; він потрібен лише
для локальних семантичних ембединґів.

## Повний експеримент з Gemini

Створіть власний `.env` (файл не потрапляє в Git) та впишіть ключ локально:

```powershell
Copy-Item Lab2/.env.example Lab2/.env
```

Отримання ключа: [Google AI Studio](https://aistudio.google.com/).
В `.env`: `GEMINI_API_KEY=...`. Назви моделей змінюються через змінні середовища.
Gemini 2.5 Flash використовується для екстракції, резюме й обох RAG-відповідей;
gemini-embedding-001 — для векторів. Доступність і квоти залежать від облікового запису.

```powershell
.\.venv\Scripts\python.exe Lab2/pipeline.py --mode live --provider gemini --embeddings gemini
```

## Локальний варіант

Налаштований варіант для цього комп’ютера: Qwen3 4B Instruct для LLM та Qwen3 Embedding
0.6B для семантичного пошуку. Ключ API не потрібен. Обидві моделі виконуються
локально; інтернет потрібен для початкового встановлення і завантаження.
Параметри зберігаються у `Lab2/.env`; використовується саме Instruct-варіант
для прямих відповідей. Контекст — 4096 токенів. Ліміт екстракції — 4096 токенів,
резюме спільноти — 256, фінальної RAG-відповіді — 1536.

```powershell
ollama pull qwen3:4b-instruct
ollama pull qwen3-embedding:0.6b
.\Lab2\run_lab.ps1
```

`run_lab.ps1` запускає сервер у фоні, якщо він ще не працює, і виконує повний
пайплайн. Можна також запустити напряму:

```powershell
.\.venv\Scripts\python.exe Lab2/pipeline.py --mode live --provider ollama --embeddings ollama
```

Назви моделей змінюються через `OLLAMA_MODEL` і `OLLAMA_EMBEDDING_MODEL`.
Альтернатива: `--embeddings local` використовує багатомовну SentenceTransformer
і потребує встановлення `sentence-transformers` та першого завантаження її ваг.

Після повного запуску можна шукати у збереженому індексі без повторної екстракції:

```powershell
.\.venv\Scripts\python.exe Lab2/search_saved.py "У салоні душно, а з дефлекторів ледь дме. Що оглянути?"
```

## Пайплайн

1. Читає 10 документів і розбиває на 140 слів із перекриттям 30, без змішування документів.
2. У live викликає structured output Gemini або JSON Schema Ollama; перевіряє Pydantic, типи кінців ребер, дослівність цитат, напрям і лексичне підтвердження сутностей; вимагає ≥30 прийнятих фактів. V2 підтримує явні позитивні твердження; умовні та заперечні відхиляє.
3. Зливає однакові назви сутностей (тип + NFKC/casefold/пробіли), зберігає походження фактів.
4. Отримує семантичні вектори через Gemini, Ollama або SentenceTransformer; зберігає NumPy-сховище, порівнює cosine top-3 з TF-IDF для 5 запитів.
5. Будує MultiDiGraph, GraphML, PNG, SVG; знаходить Louvain-спільноти на зваженій проєкції.
6. Підсумовує спільноти тим самим LLM, синтезує GraphRAG-відповідь і окрему vector-RAG-відповідь з top-3 чанків.
7. Зберігає звіт і випадкові 20 фактів (seed=42) для ручного аудиту.

## Результати

`output/demo/` — демонстраційні артефакти без LLM.
`output/live/` — остаточні результати повного запуску.
`output/improved_v2/` — збережений повторний експеримент V2.
`output/baseline_v1/` — початковий експеримент та аудит 40% для порівняння.
`output/initial_thinking_run/` — незавершений діагностичний запуск початкової моделі;
його не слід використовувати як остаточні результати.

- `facts.json` — факти зі схемою, цитатами та doc_id.
- `rejected_facts.json` — невалідні LLM-факти (live).
- `chunks.json`, `embeddings.npy`, `vector_store.json` — векторне сховище та метадані.
- `search_comparison.json` — top-3, Hit@1 і Recall@3.
- `knowledge_graph.graphml`, `.png`, `.svg` — граф і візуалізація.
- `communities.json`, `community_summaries.json` — спільноти та їх резюме.
- `rag_answers.json` — дві відповіді на глобальне запитання.
- `manual_review.csv` — 20 фактів з оцінками й поясненнями перевірки асистентом.
- `review_summary.json` — підсумок 20/20 = 100% у вибірці V2 і контрольні суми вихідних даних.
- `raw_facts.json`, `rejected_facts.json` — сирі кандидати й причини відхилення.
- `run_metadata.json` — режим, походження фактів, модель, хеш корпусу.
- `report.md` — звіт із фактичними результатами поточного запуску.
